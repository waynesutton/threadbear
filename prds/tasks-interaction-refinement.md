# Tasks interaction refinement

Created: 2026-11-17 UTC
Status: implementation in progress; not deployed.

## Requested behavior

- Up/Down select visible tasks without stealing arrows from text inputs; Enter opens selection. Escape closes editor/confirmation/menu first and preserves unsaved drafts.
- Delete always asks in the app's own confirmation dialog, then retains existing Undo.
- Appearance offers Light and Dark, initially following the app. Foreground/background colors come from the selected theme; remove custom color/font controls. Preserve photo upload, fade and positioning; repair native picker/upload.
- Lists fit desktop and mobile. Board owns horizontal scrolling within its pane; columns have usable widths and vertical scrolling, no content clipped by the window.
- Rename the built-in columns and add custom columns; stable identifiers keep task membership intact across renames, ordering and sync. Click an empty column area or its plus to add there.
- Remove decorative checkbox from the quick-add field. Match the project page Tasks tab typography to its Project tab.
- Send to thread in task menu/editor starts a thread with title/notes/project context. Busy and error states prevent duplicate launches. Show the associated thread afterward. Do not execute task content just by inspecting Tasks.

## Compatibility and data proposal

Keep canonical status backlog/todo/doing/done for completion and older clients. Add optional columnId on tasks and optional column definitions in preferences (stable id, name, canonical status). Existing tasks resolve to their status column. Renaming changes display only; custom columns default to todo behavior. Additive fields only, no destructive migration. Thread association must include runnerId/threadId and retry-safe creation; use existing thread creation/relay paths and permission defaults rather than a new agent launch mechanism. Allocate backend version after checking current main (85 already used by completion cards).
